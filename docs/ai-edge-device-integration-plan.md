# AIOT IoT 센서 / AI EDGE 디바이스 연동 계획

작성일: 2026-09-17. 로컬 기준: `feat/led-message-dispatch`, `c190c25`.

목표: KETI 연동 IoT 센서와 외부 업체 연동 AI EDGE 디바이스(CCTV·MIC)를 구분하고, 동기화 → 목록 → 위치 확인·보정 → 지도 관제 흐름을 제공한다.

## 확인 근거와 범위

- 최신 OpenAPI: https://dev.pluxity.com/aiot/api/api-docs (OpenAPI 3.1.0, API 버전 1.0.0).
- 명세와 로컬 프론트 코드를 비교하고 인증 정보 없는 GET 요청만 실행했다. 동기화 POST, 좌표 PATCH, 장비 제어는 실행하지 않았다.
- `GET /mics`: HTTP 200, 4대, 상태는 모두 `ACTIVE`. 위도·경도 쌍이 있는 장비 0대, 소속 공원이 있는 장비 0대.
- `GET /mics/events?page=1&size=1`: HTTP 200, 이벤트 1건 확인.
- `GET /cctvs`: HTTP 403. 인증된 사용자의 장비 수·좌표·공원 매핑은 미확인.
- `GET /cctvs/events?page=1&size=1`: HTTP 200, 이벤트 1건 확인.
- 위 응답은 확인 시점의 결과다. 동기화 성공, 실시간 알림, 스트림 재생까지 검증된 것은 아니다.

## 1. 도메인과 화면 구조

```text
디바이스
├─ IoT 센서 (KETI / 현재 Mobius 연동)
│  └─ 기존 센서 유형 및 Feature 유지
└─ AI EDGE 디바이스 (외부 업체 연동)
   ├─ CCTV (EDS)
   └─ MIC (AI 마이크 업체)
```

- 운영 메뉴: 기존 `IoT 센서`를 유지하고 `AI EDGE 디바이스` 목록을 추가한다. AI EDGE 내부에 전체/CCTV/MIC 필터를 둔다.
- 시설 관리: 기존 `CCTV 관리`를 `AI EDGE 디바이스 관리`로 확장한다. 공통 목록 컴포넌트를 재사용하고 ADMIN에게 동기화·위치 설정 작업을 제공한다.
- 기존 `/devices/cctv` 접근은 새 관리 화면의 CCTV 필터로 연결해 기존 진입점을 유지한다.
- 관제 목록은 로그인 사용자에게 제공하되 공원별 조회 권한은 백엔드에서 보장한다. 현재 `useSiteAccess`의 resourceType 추정 정규식을 확정 계약처럼 재사용하지 않는다.
- 라이브 CCTV 모니터링 재활성화와 MIC 오디오 재생은 이번 목록·지도 범위에 포함하지 않는다. 지도 상세에서는 장비 정보와 제공 가능한 이벤트를 먼저 연결한다.

## 2. API 확인 결과

| 기능 | CCTV | MIC |
|---|---|---|
| 목록 | `GET /cctvs?siteId=` | `GET /mics`, 쿼리 필터 미기재 |
| 외부 업체 동기화 | `POST /cctvs/sync` → 204 | `POST /mics/sync` → 204, 업체 호출 실패 502 |
| 개별 상세 | `GET /cctvs/{id}` | 문서에 없음; 조회한 목록에서 상세 구성 가능 |
| 설치 좌표 | `lon`, `lat` | `longitude`, `latitude` |
| 소속 공원 | `site` | `site` |
| 좌표 저장 | `PATCH /cctvs/{id}/coordinates`, 본문 `{lon, lat}` | 문서에 없음 |
| 공원 배정 | CCTV 좌표 수정 시 서버가 자동 매핑한다고 명시 | 매핑 규칙 미기재 |
| 이벤트 | `GET /cctvs/events?page=&size=&from=&to=` | `GET /mics/events?page=&size=&micId=&from=&to=` |
| 추가 데이터 | 실시간·녹화 스트림, 군중계수 최신값·시계열 | 라벨·신뢰도·최대/평균 소음·소음 배열·감지 기준값 |

추가 계약 사항:

- 목록 응답은 `data: []`, 이벤트는 `data: {content, pageNumber, pageSize, totalElements, first, last}` 구조다.
- 이벤트 페이지는 1부터 시작한다. 기본 size=9999이므로 프론트에서 명시적으로 20~50을 전달한다.
- 기간 파라미터 형식은 `yyyyMMddHHmmss`이며 서버가 해석하는 시간대는 확인이 필요하다.
- MIC 이벤트의 `micId`는 DB의 숫자 `id`가 아니라 업체 ID `vendorMicId`에 대응한다.
- CCTV 이벤트의 `cameraId`와 장비 `edsCameraId`의 연결은 기존 프론트가 사용하는 방식이며 인증된 샘플로 최종 확인한다.
- CCTV 이벤트에는 공원·카메라 필터 파라미터가 문서화되어 있지 않다. 한 페이지를 클라이언트 필터링한 결과를 전체 장비별 이력·통계로 표시하지 않는다.
- 장비 수동 생성·삭제, MIC 임계값 수정, 외부 업체 연결 설정 API는 관련 컨트롤러 명세에서 확인되지 않았다. 우선 외부 등록 장비를 동기화해 가져오는 방식으로 설계한다.
- OpenAPI의 servers URL은 HTTP다. 프론트는 문서의 해당 값을 그대로 사용하지 않고 배포 HTTPS `/aiot/api`와 현재 API 클라이언트 설정을 사용한다.

## 3. 현재 코드와의 차이

| 항목 | 현재 코드 | 개발 방향 |
|---|---|---|
| CCTV 상태 | `number`, 0/1/2로 뱃지 처리; 플레이어 목록도 `=== 1` | 명세의 `DISCONNECTED / NORMAL / FAULT` 적용 |
| CCTV 유형 | 소문자 `ip / ptz / ai ...` | 명세의 대문자 enum 적용 |
| CCTV 목록·동기화 | `CCTV.tsx`, `useCctv.ts` 구현됨 | 재사용·확장 |
| CCTV 좌표 | 수정 훅과 `LocationPicker` 존재, 관리 목록에 편집 흐름 없음 | 위치 설정 다이얼로그 연결 |
| MIC | 전용 타입·훅·페이지 없음 | API 타입부터 신규 구현 |
| 지도 | `CesiumMap`은 `FeatureResponse[]`를 센서로 받음 | 장비 공통 지도 모델과 AI EDGE 레이어 추가 |
| 마커 정리 | `clearAllMarkers()`가 `viewer.entities.removeAll()` 호출 | 레이어 소유 마커만 제거하도록 분리 |
| 이벤트 | AI EDGE 탭은 CCTV 이벤트만 표시 | 후속 단계에서 CCTV/MIC 구분 추가 |

## 4. 연동과 목록 운영 흐름

```text
관리자가 CCTV 또는 MIC 동기화 실행
  → AIOT 백엔드가 해당 업체 서버를 조회·반영
  → 성공 응답 후 해당 종류의 장비 목록 재조회
  → 공원 매핑 / 위치 미등록 / 공원 미매핑 상태 확인
  → 좌표가 없는 장비 위치 등록 또는 업체 데이터 보완
  → 서버 좌표·공원 결과 재조회
  → 운영 목록·대시보드·지도에 동일 데이터 반영
```

- 브라우저는 업체 접속 정보·인증을 직접 취급하지 않고 AIOT API를 호출한다.
- 초기 화면은 DB 목록 조회만 수행한다. 목록을 열 때마다 업체 동기화를 실행하지 않는다.
- CCTV와 MIC 동기화 버튼을 나누고 종류별 진행·실패를 표시한다. 한 업체의 실패가 다른 업체 목록을 가리지 않도록 한다.
- 204는 추가·수정 건수를 제공하지 않으므로 임의의 동기화 처리 건수를 표시하지 않는다. 성공 후 전체 재조회 건수는 별도로 표시할 수 있다.
- 동기화 후 공원 필터별 캐시, 장비 상세 캐시, 공통 지도 데이터까지 갱신한다.
- 공통 목록 컬럼: 종류, 이름, 업체 장비 ID, 원본 상태, 공원, 위치 등록 여부, 상세/지도 이동.
- MIC 추가 정보: edgeId, host, 감지 기준값. CCTV 추가 정보: 카메라 타입, IP, 영상 분석 설정.
- MIC ACTIVE를 곧바로 '통신 정상'으로 단정하지 않는다. 상태 의미가 확정될 때까지 활성/비활성/연결 끊김 등 원본 의미를 유지한다.
- 목록 로딩·빈 결과·권한 오류·업체 연동 실패를 구분한다.

## 5. 지도 표시 설계

API DTO는 종류별로 유지하고, 렌더링에 필요한 속성만 공통 모델로 변환한다.

```ts
type DeviceCategory = 'IOT_SENSOR' | 'AI_EDGE'
type DeviceKind = 'IOT_SENSOR' | 'CCTV' | 'MIC'

interface MapDevice {
  key: string // iot:1, cctv:1, mic:1 — 종류 간 ID 충돌 방지
  category: DeviceCategory
  kind: DeviceKind
  id: number
  externalId: string
  name: string
  siteId: number | null
  position: { longitude: number; latitude: number; height?: number } | null
  sourceStatus: string | null
}
```

- 공원별 보기에서 선택 공원의 IoT/CCTV/MIC를 함께 표시하고 레이어 토글을 제공한다. 전체보기는 공원 마커를 기본으로 유지하며 장비 레이어는 별도로 선택하게 한다.
- 장비별 아이콘으로 종류를 구분하고, 색상 의미는 상태 매핑표로 정의한다. 연결·활성 상태와 이벤트 위험 등급은 별개다.
- 좌표가 없거나 유효하지 않으면 마커를 생성하지 않고 목록에 `위치 미등록`으로 표시한다. 이벤트 발생 좌표를 설치 위치로 대체하지 않는다.
- 위경도의 null·유한수·범위를 검증한다. 0이라는 이유만으로 개별 위도/경도를 버리지 않으며 `(0,0)` 센티널 여부는 서버 계약으로 결정한다.
- 위치는 유효하지만 site가 없는 장비는 `공원 미매핑` 목록과 전체 장비 레이어에서 확인 가능하게 한다. 임의의 공원에 넣지 않는다.
- 마커 클릭 → 장비 상세, 목록의 지도 이동 → 동일 마커로 카메라 이동·선택. 선택 키에도 종류를 포함한다.
- AI EDGE 레이어는 자체 엔티티 목록 또는 CustomDataSource를 소유한다. 갱신·토글 시 공원 폴리곤이나 다른 장비 레이어를 삭제하지 않는다.
- 단순 상태 갱신에 Viewer를 재생성하지 않는다. 페이지 이탈 시 마커·이벤트 핸들러·점멸 리스너를 정리한다.
- 설치 높이는 CCTV/MIC 명세에 없다. 초기 지형 부착 표시를 사용하고, 모델에 가려지는 문제가 있으면 높이 필드를 백엔드 계약에 추가한다.

## 6. 선행 확인 및 백엔드 협의

1. **MIC 위치 확보 — 지도 표시의 실제 선행 조건**
   - 실제 4대 모두 사용 가능한 설치 좌표·공원이 없다.
   - 업체 좌표를 동기화하도록 보완하거나 플랫폼에 좌표 저장 API를 추가해야 한다.
   - 제안 계약: `PATCH /mics/{id}/coordinates {longitude, latitude}` → 204 + 서버 공원 자동 매핑. 이는 현재 API가 아니라 신규 제안이다.
   - 업체 데이터 보완과 좌표 편집 중 확정된 방식으로 영속 저장하고, 재조회·재동기화 후에도 정상 위치가 유지되어야 한다.
2. **좌표 소유권·동기화 정책**
   - CCTV/MIC 동기화가 수동 보정 위치를 덮어쓰는지, 외부에서 사라진 장비를 삭제·비활성화하는지 명세에 없다.
   - 수동 좌표 보존 여부와 중복 방지 키를 확정한다. 동기화 후 동일 업체 ID가 중복 등록되지 않아야 한다.
   - IoT의 `POST /features/sync`는 `overwriteLocation=true` 기본값이 명시되어 있다. 기존 프론트는 값을 전달하지 않으므로 IoT 좌표 정책과 혼동하지 않는다.
3. **공원·권한**
   - MIC 공원 자동 매핑 및 경계 밖/경계 중첩 처리, CCTV 목록의 사용자별 조회 권한을 확인한다.
   - 인증 없는 MIC·이벤트 GET은 200, CCTV 목록은 403이었다. 의도된 정책인지 확인한다. 문서에 securitySchemes가 없다는 사실만으로 권한 정책을 단정하지 않는다.
   - 서버가 허용 장비만 반환하도록 보장하며, UI의 공원 필터를 권한 검증 대체 수단으로 삼지 않는다.
4. **이벤트와 실시간성**
   - MIC STOMP topic·재연결 후 복구 계약은 현재 REST 문서에서 확인할 수 없다.
   - 우선 명시적 새로고침/활성 화면의 제한적 폴링을 사용하고, topic이 확정되면 구독 방식으로 확장한다.
   - MIC 이벤트에는 조치 상태·심각도가 없다. IoT 이벤트의 ACTIVE/RESOLVED나 위험 등급으로 임의 변환하지 않는다.
   - 대시보드 sensor-summary의 sensorTypeStatus에는 IoT 유형만 나열되어 있다. AI EDGE 집계 지원 여부를 확인하고 기존 센서 통계에 합산하지 않는다.

## 7. 개발 작업 순서와 완료 기준

각 작업은 별도 검증 가능한 단위로 진행한다. 백엔드 작업은 이 프론트 저장소 밖의 의존성이다.

| 순서 | 작업 / 예상 범위 | 완료 기준 | 검증 | 의존성 / 주요 파일 |
|---|---|---|---|---|
| 1 | CCTV API 계약 보정 / S | 상태·타입 enum 정합, unknown fallback, 기존 목록 유지 | 문자열 상태 fixture·타입 검사 | 없음; `types/cctv.ts`, `devices/cctv/CCTV.tsx`, `CctvCameraList.tsx` |
| 2 | MIC 타입·목록·동기화 훅 / M | 목록과 204 동기화 처리, 502 오류 표시용 정보 전달, null 좌표 허용 | 응답 fixture·훅 통합 검증 | 없음; 신규 `types/mic.ts`, `hooks/useMic.ts`, 각 barrel |
| 3 | AI EDGE 조회 목록 / M | 전체/CCTV/MIC 및 공원·상태·미등록 필터, 한 종류 실패 시 부분 조회 유지 | 각 종류·빈 목록·부분 실패 화면 확인 | 1,2; 신규 목록 페이지·공통 테이블·필터, `App.tsx`, `menu.ts` |
| 4 | 관리자 동기화 흐름 / M | 종류별 진행·실패 표시, 연속 실행 방지, 성공 후 모든 관련 목록 갱신 | 동기화 성공·실패·재시도 및 권한 확인 | 3; 공통 목록, 관리 페이지, 종류별 훅 |

### 화면 구성 후속 반영

- 시설 관리의 `IoT 센서 관리` 메뉴를 실제 화면 제목과 동일한 `센서 카테고리 관리`로 변경했다.
- AI EDGE 목록은 화면 높이에 따라 페이지당 행 수를 조절한다. 지도와 상세는 오른쪽 영역을 번갈아 사용하고, MIC 상세는 기본 정보·감지 기준값·감지 이벤트 탭으로 나눴다.
- 감지 기준값은 6개씩, 감지 이벤트는 실제 API에서 3개씩 조회하여 페이지 이동으로 확인한다. 목록의 가로 스크롤과 이벤트의 내부 세로 스크롤을 제거했다.
- 실제 로그인 데이터로 1440×900, 1366×768, 1024×768 데스크톱에서 목록·상세 레이아웃을 확인했으며, 1366×768 지도에서도 문서 스크롤이 발생하지 않았다. 작은 화면에서는 내용 접근을 위해 자연스러운 세로 배치를 유지한다.
- IoT 센서도 같은 목록/지도/상세 구성과 화면 높이 기반 페이지 처리를 적용했다. 기존 지도 팝업을 제거하고 센서 선택·지도 이동·마커 선택을 연결했다. 공원·카테고리·검색 필터와 활성화·동기화 기능은 유지한다.
- 공통 지도 레이어는 `IoT 센서`와 `AI EDGE 디바이스`를 같은 계층에 두고, `CCTV`·`MIC`는 AI EDGE 아래에 배치한다. 부모 체크박스는 자식 전체 선택/해제와 부분 선택 상태를 반영한다. 각 수치는 좌표가 유효한 표시 가능 장비 수다.
- 관리 화면은 종류별로 분리한다. IoT 화면은 IoT 센서만, AI EDGE 화면은 CCTV/MIC만 조회·표시하며 해당 범례만 제공한다. 대시보드는 전체 종류를 기본 표시하고 범례에서 IoT 및 AI EDGE(CCTV/MIC)를 선택한다.
- 실제 IoT 117대와 중앙공원 필터 2대, 센서 위치 이동·상세 표시, IoT 독립 토글 및 AI EDGE 전체/부분 선택을 브라우저에서 확인했다. 타입 검사·프로덕션 빌드·기존 회귀 테스트 8개가 통과했다. 검증 중 서버의 동기화·활성화 상태는 변경하지 않았다.

### 관리 기능과 변경 API (2026-09-17 명세 재확인)

| 대상 | 실제 API | 화면 연결 |
|---|---|---|
| IoT 정보 수정 | `PUT /features/{id}` · `active`, `height` | 활성화 스위치, 표의 고도 입력·저장, 상세 정보 수정 창 |
| IoT 동기화 | `POST /features/sync?overwriteLocation=boolean` | 동기화 창에서 좌표 유지(false, 기본 선택) 또는 Mobius 좌표·공원 덮어쓰기(true) 선택. 목록 필터와 관계없이 전체 센서 대상임을 표시 |
| CCTV 동기화 | `POST /cctvs/sync` | 관리자 CCTV 동기화 버튼 |
| CCTV 좌표 수정 | `PATCH /cctvs/{id}/coordinates` · `lon`, `lat` | 표의 위도·경도 입력·저장 및 좌표 수정 창, 저장 후 서버 공원 매핑 결과 재조회 |
| MIC 동기화 | `POST /mics/sync` | 관리자 MIC 동기화 버튼 |
| Mobius 연동 설정 | `POST /mobius/api-url` · `url` | 기존 시스템의 Mobius 연동 관리 화면 |

IoT와 MIC의 위도·경도 직접 수정 API, IoT/CCTV/MIC 장비 삭제(DELETE) 및 수동 장비 생성 API는 현재 명세에 없다. IoT `PUT`에 위도·경도를 임의로 추가하지 않는다. 직접 좌표 편집이 필요하면 백엔드 계약 확장이 선행되어야 한다. 현 화면에서는 IoT 위도·경도 조회 및 연동 갱신, CCTV 좌표 직접 수정까지 제공한다.

IoT 활성화는 명세와 실제 조회 응답의 필드명이 다르다. 실제 `GET /features`의 `isActive`를 조회 훅에서 화면의 `active`로 변환하며, 명세 형태의 `active` 응답도 지원한다. 명시적인 `isActive: false`를 보존하고 수정 요청은 명세대로 `{ active }`를 전송한다. 실제 목록·상세·편집의 활성화 표시와 회귀 테스트로 확인했다.

관리 지도는 공원 모델을 포함한 모든 3D 타일셋·지형 로딩을 제외한다. 지역구 레이어·버튼도 제외하며, `GET /sites`의 실제 WKT로 공원 영역과 이름만 표시한다. 공원 영역 체크박스와 각 화면에 해당하는 장비 범례를 제공한다. 대시보드의 3D 지도와 범례 선택은 유지한다.

### API 작업에 맞춘 인터페이스 정리

- IoT·AI EDGE 모두 지도를 기본으로 열고, 표에서 장비 이름을 선택하면 지도에 해당 장비를 표시한다. 행별 지도 아이콘을 제거하고 상단 지도 토글을 유지한다.
- 지도 표시 여부와 관계없이 표에 위도·경도를 표시한다. IoT는 위도·경도를 한 열에 세로로 표시하고 고도 입력 열을 제공한다. AI EDGE는 위도와 경도를 별도 열로 나누며 고도 열은 표시하지 않는다. 지도 위 선택 장비 요약에서는 중복 위도·경도를 제거한다.
- IoT 고도와 관리자 CCTV 위도·경도를 표에서 직접 입력하고 `저장`한다. 변경된 유효한 값이 있을 때만 저장할 수 있다. 저장 실패 시 입력을 유지한다.
- IoT의 고도 값이 없으면 화면 기본값은 0이다. MIC는 직접 수정 API가 없어 저장할 수 없다. 기본 표시값을 서버에 자동 저장하지 않는다.
- IoT 편집 창은 디바이스 ID·위도·경도를 조회 전용 영역에 표시하고, 활성화·높이 중 바뀐 값만 PUT으로 보낸다. 높이 0과 활성화 false도 유효한 값으로 보존한다.
- IoT 동기화는 `현재 위치 유지`와 `연동 위치 반영` 중 하나를 선택한다. CCTV/MIC 동기화 창에는 공급사와 전체 종류 대상임을 안내하고 실행한다.
- IoT 수정·동기화 훅이 목록 캐시 갱신까지 처리하여 지도·상세도 최신 응답을 사용한다. 편집 화면의 중복 재조회는 제거했다.
- 권한 부족(403), 장비 없음(404), 업체 연결 실패(502)를 구분하여 안내한다. IoT PUT의 403은 편집 창에서 처리하여 입력을 유지한다.
- 변경하지 않은 CCTV 좌표와 유효하지 않은 좌표는 저장할 수 없으며 저장 중에는 지도 위치 선택을 잠근다.
- 타입 검사·빌드 및 활성화 응답을 포함한 회귀 테스트 10개 통과. 실제 데이터로 인라인 고도·좌표의 변경/복원/유효성에 따른 저장 버튼 상태를 확인했다. 1024×768, 1440×768에서 표·페이지 스크롤 없이 표시되며, 관리 지도에서 3D·지역구 리소스 요청이 없음을 확인했다. 실제 수정/동기화 요청은 실행하지 않았다.

### 리팩토링 (2026-09-18)

- `SensorTableRow`와 `DeviceTableRow`를 분리했다. 입력 초안은 상위 표에 유지하여 페이지·필터 이동 후에도 보존하고, 저장 성공 시 제출한 값과 일치하는 초안만 정리한다.
- `getCoordinateEditState`와 `getHeightEditState`로 표·팝업의 검증 및 변경 판정을 공통화했다. 빈 입력, 0, 기존 좌표 정밀도, 범위 밖 좌표, 유효하지 않은 숫자에 대한 회귀 검증을 추가했다.
- `useParkAreaLayer`로 공원 WKT 표시와 생성 엔티티 정리 책임을 분리했다. 장비 마커·지역구 엔티티와 공원 영역의 수명 관리를 구분한다.
- API 요청 필드·권한·캐시 갱신 방식과 화면 배치는 유지한다. 기존 테스트 10개와 신규 경계값 테스트 2개가 통과했다. 타입 검사와 프로덕션 빌드도 통과했다.
- ESLint 실행은 기존 `eslint.config.*` 파일 부재로 실패했다. 전체 린트 설정 도입은 이번 코드 구조 정리 범위에서 제외한다.
- 재로그인 후 실제 API 조회 200을 확인하고 IoT 고도·CCTV 좌표의 변경/유효성/복원, 페이지 이동 후 입력 보존, 공원 영역 토글을 브라우저에서 재검증했다. 1024×768 및 1440×768 표 배치를 확인했으며 페이지 오류와 장비 저장·동기화 요청은 발생하지 않았다.
